## 1. Why Apple rejected it

Guideline 2.1 – Information Needed. Apple did not report a bug. It asked for six things in the
App Review **Notes**:

1. A screen recording from a physical device on the latest iOS. It must start at app launch and
   show registration, login, account deletion, **content reporting and blocking**, and any paid
   content.
2. The app's purpose and audience, the problem it solves and the value it provides.
3. Set-up and access instructions, including demo credentials.
4. The external services the app uses.
5. Any regional differences.
6. Authorisation documents if the app is in a regulated area.

## 3. Blockers and fixes

### 3.1 Block user is missing: code change and new build required

Apple's message says the recording must show "the required content reporting **and blocking**
mechanisms" (Guideline 1.2). This can't be met with the current build.

**Implemented on branch `feature/community-block-user` (not committed, not deployed):**

- **OpsAPI plugin:** new table `pintopets_forum_blocks` (migration 20261126170001), CRUD
  resource `forum-blocks`, `GET /forum/users/:uuid/blocks`, and `/forum/threads?viewer=` now
  leaves out blocked authors.
- **API:** `GET/POST /api/v1/community/blocks` and `DELETE /api/v1/community/blocks/{blockId}`.
  You block by a post (thread or reply), so user ids are never exposed. Thread lists, thread
  detail and replies hide blocked authors for the blocker only. Only the blocker can see or
  remove their blocks. Account deletion removes blocks both ways.
- **iOS:** "Block" next to Report on threads and replies, a confirmation dialog (with a
  "Report instead" option), and Account → Blocked people with Unblock.
- **Not done:** a Block button on the website (the backend filtering already applies there).
  Blocking does not file a report automatically; the dialog offers Report.
- **Tests,** then int, then prod (each needs approval), then a new build (for example
  1.0.0 build 2026112xxxxx) uploaded to TestFlight. Approval required.

### 3.2 Registration path: Option B chosen, with email verification (plan: `registration-option-b-plan.md`)

Prod sign-in uses OpsAPI's password-only page (Google was removed for guideline 4.8). That page
has no "Create account". If no public sign-up exists anywhere, new customers can't use the app,
and Apple may treat it as incomplete (2.1) or as for existing customers only (3.2).

Owner to confirm one of these:

- (a) OpsAPI has a public sign-up URL. Then link it from the hosted page or the app, and show
  it in the recording.
- (b) Add email sign-up to OpsAPI's hosted page. This is in the OpsAPI repo, not this one.
- (c) Turn on Sign in with Apple. It creates accounts and is already wired in code
  (`appleSignIn: false` in prod). OpsAPI needs Apple keys and token revocation.

### 3.3 Empty prod forum

Before recording, post one or two real, kind discussions from a second account you own. The
reviewer then has content to report and block. Don't post from the demo account; the
recording blocks the other account's post.

### 3.4 Minor

The website's top menu says "Ask AI" but there is no AI behind it. Rename it (for example to
"Ask a question") so the notes can truthfully say "no AI services".

## 4. Can build 202611251521 be resubmitted?

The build is technically valid (VALID, not expired, prod API). But it **has no blocking**, and
Apple explicitly asks to see blocking. So a **new build is needed** once 3.1 is done (and 3.2,
if the fix touches the app). A build with no code changes could only go back if Apple accepted a
UGC app without blocking, which its message rules out.

## 5. Physical iPhone recording script

Needs a real iPhone on the latest iOS (26.x), the new build installed from TestFlight, and Screen
Recording in Control Centre. Turn on Do Not Disturb. Stay silent or narrate. Aim for 3–5 minutes.
Do it in one take, with no cuts.

**None of the following can be verified from the codebase.** Every step must be done on the
device.

0. Delete PintoPets from the phone first, then install it fresh from TestFlight. Start the
   recording from the Home Screen.
1. **Launch:** tap the PintoPets icon. The signed-out welcome screen appears.
2. **Registration:** tap "Sign in or create an account", then create a new throwaway account
   (depends on the §3.2 choice). Show the confirmation and arrival in the app.
3. Sign out. **Login:** tap "Sign in or create an account" again, enter the demo email and
   password (blur the password afterwards, or type it off-screen) and return to the app.
4. **Dashboard / My Pets:** show the seeded household list.
5. **Pet profile:** open a pet and scroll through its details (species, breed, microchip).
   Tap Edit, change one field, Save.
6. **Add a pet:** My Pets → Add a pet, fill in name and species, Save.
7. **Photos:** on a pet, add a photo from the library and show it appear.
8. **Health records:** open a record list (vaccinations, worming), then Weight → add a weight →
   Save.
9. **Reminders tab:** show overdue / due soon.
10. **Community:** open the Community tab, open a discussion, reply, and tap Helpful.
    Show the guidelines link.
11. **Report:** on a post, tap Report, choose a reason and send. Show "Thank you. A moderator
    will take a look."
12. **Block:** on the other account's post, tap Block, confirm, and show the post disappear.
    Open Account → Blocked people and show the entry. (Needs the §3.1 build.)
13. **Account deletion (use the throwaway account from step 2, never the demo account):** sign
    in as it, Account → Delete account and data → web page → sign in again → type DELETE →
    confirm → show the "account deleted" result, then return to the app, now signed out.
14. **Logout:** sign in as the demo account, Account → Sign out → confirm.
15. Stop the recording. Trim only the dead time at the end. Export at 1080p or better.

Upload: App Store Connect → App Review Information → **Attachment**, if the field is offered.
Otherwise share an unlisted link (iCloud Drive or Google Drive, "anyone with the link") and
paste it into the Notes.
